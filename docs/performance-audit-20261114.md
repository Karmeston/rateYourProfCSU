## 11 月 23 日：按实际读取行数计费

本地临时库实测（3000 门课、约 2000 条评价，其中一门 60 条评价、300 个投票）：精简详情读 2 行，评价少的课程读评价约 12 行，热门课最新排序约 355 行、最有帮助排序约 748 行，学习资料 2 行，评分汇总约 4100 行。原先详情与评价每次固定扣 500，普通浏览被高估约 60 倍。

- 读取类功能（目录、专业查课、筛选选项、详情与评价）先按估算放行，详情与评价估算降为 50。Worker 统计本次请求 D1 返回的 `rows_read`，超出估算时在响应后向额度守卫补记差额；补记只计数、不拒绝，额度用尽后从下一次请求开始拦截。只有超出估算的请求才多一次 Durable Object 调用。提交和浏览量上报仍用原估算权重。
- 读取预算合计仍低于 D1 免费版每天 500 万行：详情与评价 230 万（单网络 57.5 万，约四分之一，照顾共用出口的校园网），仅 API 调用方使用的目录 105 万、筛选选项 70 万、专业查课 40 万。线上课程广场使用静态目录，不经过这几类目录额度。
- 无有效访客 Cookie 的评价分页请求先查边缘缓存，缓存 60 秒；命中时不做限流、不扣额度、不读 D1。缓存只存匿名视图，不含本人评价或投票。评价、回复、投票、举报成功后，清除该对象最新和最有帮助两种排序、各星级的首页缓存，只影响当前节点，其他节点最多延迟 60 秒。
- 课程详情先在静态目录中查找课程；非公选课直接用目录里的名称、代码、学院和类别显示，不再请求 `/api/courses/:id`。公选课需要认定说明，旧课程编号需要跳转，目录加载失败时也回到原接口。
- Cloudflare Cache API 在 `*.workers.dev` 上不生效，评价缓存、评分汇总缓存和目录 API 缓存都需要通过自定义域名访问才起作用。

免费版的其他上限：Workers 和 Durable Object 每天各 10 万次请求。打开一次详情约需 2 到 3 次 API 请求（评价、浏览量上报，公选课另加详情），日均几万次课程浏览前就会先碰到请求数上限。
