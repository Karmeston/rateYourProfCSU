# 2026-11-14 性能核查

用发布后生产快照（12,629 门课程、62,716 条课程来源记录）运行应用的查询并检查 SQLite 执行计划。查询次数是应用调用的 SQL 语句数，不等同于 Cloudflare 计费读取行数。前端体积比较首页入口的生产构建，按同一 gzip 方法压缩。

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 首页入口 JS | 283,282 字节；gzip 87,195 字节 | 242,215 字节；gzip 76,202 字节（少 12.6%） |
| 搜索“数学”，冷缓存首屏 | 2 条 SQL，各扫描一次课程候选 | 1 条 SQL，同时返回结果和总数 |
| 重复访问同一个课程列表 | 每次执行查询 | 60 秒边缘缓存命中时，不读数据库 |
| 普通课程详情 | 2 条 SQL | 1 条 SQL；只读页面需要的数据 |
| 无访客 Cookie 的评价列表 | 2 次数据库调用、4 条 SQL | 1 次批量调用、3 条 SQL |

冷缓存下，首页列表也与专业选项解耦，列表只查分页与课程总数。专业选项故障不会连带中止课程列表请求。

详情及评分表单、使用指南和教师页按需加载。课程列表缓存仅含公共数据，键包含全部筛选和分页参数；评分列表、投稿和后台不共享缓存。短缓存期间，课程列表的评分汇总可能比详情晚约一分钟更新。错误和空结果不写入列表边缘缓存。精简的课程详情请求不读取官方材料；旧 API 保持兼容。

仍需留意：任意子串查询冷缓存仍要扫描课程候选；评分优先排序需要汇总公开评价；专业和学院选项的冷缓存仍需聚合。后台统计和评分互动目前保持在各自接口，没有加长缓存，也没有移除现有功能。流量统计每次记账仍有写入成本；若用量再次接近额度，优先看 Cloudflare 的读取和写入指标，再决定是否为搜索加索引或调整统计频率。
